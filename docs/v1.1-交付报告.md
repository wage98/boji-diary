## 二、桌宠：动作优先（参照 Shimeji）

### 2.1 GitHub 调研结论

参照了 **Shimeji-ee / Clover_Shimeji** 这一系。它们的做法正好是你要的方向：

- 用 `behaviors.xml` 定义 **idle / walk / drag / fall / sit / sleep** 的行为状态机，按**权重随机**触发、可被打断、结束回落 idle；
- 动作帧远多于表情帧（walk_left / walk_right / drag / fall 各自独立）；
- 空闲一段时间后进入睡眠态并显示 zzz。

### 2.2 已落地

| 能力 | 实现 | 说明 |
|---|---|---|
| **沿边溜达** | `petWalk()` | 沿停靠边位移 + 颠动 + 影子缩放，走一段再回来；**权重最高（26%）**，动作优先于表情 |
| **被抓挣扎** | `petStruggle()` | 拖动时摆动 |
| **落地回弹** | `petLand()` | 松手吸附后压缩回弹（对应 Shimeji 的 fall） |
| **打瞌睡** | 原有 `sleep` | 55s 无互动先挥手告别再睡 |
| **语音朗读** | `petSpeak()` | Web Speech TTS，**默认关闭**，设置里可开；浏览器不支持时静默降级不报错 |
| **照片做桌宠** | `photoPetSVG()` | 上传照片 → 圆形抠图当脸 + 卡通眼嘴叠加 |

两个刻意的取舍，如实说明：

1. **没做朝向镜像翻转**：`.pet-body` 的 transform 已被左右缘朝向占用，叠加会互相抵消（右缘镜像 × 朝向镜像 = 不翻），所以方向感由位移方向表达，不做半吊子的翻转。
2. **捏脸我判断先不做**：性价比低。你要的"上传照片自动做成桌宠"已经落地，它比捏脸更贴近"这是我的桌宠"的诉求；真要做捏脸（发型/瞳色/脸型多档）是另一套参数化工程，建议等照片桌宠用过一轮再决定要不要加。

**照片桌宠的边界**：端侧没有生成式模型，**做不到"照片转二次元"**。我做的是"你的照片当脸 + 卡通表情叠加"的贴纸式合成，效果可预期、不会产生幻觉脸。
