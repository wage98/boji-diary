# 训练日记 · 产品评估与开源差距清单

> 目的：如实记录当前产品的优点、缺点与潜在风险，并对照成熟 GitHub 开源项目的通行做法给出差距清单与改进优先级。
> 评估口径：以仓库当前状态（`main` @ v8.1）为准，不含计划中但未落地的功能。

---

## 一、当前的优点

| # | 优点 | 依据 |
|---|---|---|
| 1 | **零构建、零运行时依赖**：原生 HTML/CSS/JS，双击 `index.html` 即可运行，不存在依赖树与编译链断裂风险 | 仓库无 `package.json`，`app.js` / `styles.css` 直接使用 |
| 2 | **数据完全在本机**：`localStorage` 单键存储，无账号、无上传、无埋点，隐私边界清晰 | `KEY = 'boji_v7'`，全部读写在 `load()` / `save()` |
| 3 | **写入失败不再静默**：存储写满 / 隐私模式时明确提示，且不中断调用链 | v8.0 修复，`save()` 返回布尔值 + 首次失败 toast |
| 4 | **桌宠形象全部自绘**：分层 SVG 参数化，默认路径不含任何第三方角色素材，打包上架无版权障碍 | `nahidaSVG` / `spiderSVG`；官方素材仅作可切换备选，溯源见 `assets/CREDITS.md` |
| 5 | **训练数据密度高**：每个动作标注目标肌群、组数×次数、动作节奏（离心-底停-向心）、呼吸、组间休息、起始建议重量、动作标准、常见错误、教学视频 | A/B 两套共 48 个动作，字段统一 |
| 6 | **两套方案互不交叉、切换不丢数据**：切换只替换数据源，打卡 / 重量 / 自定义动作均保留 | 自检 M3 / M8 断言覆盖 |
| 7 | **行为级自检覆盖面实在**：189 项（功能回归 41 + 攻击式 148），含脏数据、越界输入、XSS、失败兜底、方案切换等 | `node tools/selfcheck.js` |
| 8 | **诚实的能力边界**：未配置 AI 时明确降级为条码 / 在线库 / 历史 / 本地匹配，绝不返回编造的识别结果；空响应判失败而不是兜底成「150 kcal」 | v8.0 修复 + README「已知边界」 |
| 9 | **离线可用**：PWA + Service Worker，页面请求网络优先，保证打开即最新版 | `sw.js` |
| 10 | **导出/导入完整**：JSON 全量备份 + CSV（打卡 / 重量 / 饮食三段，UTF-8 BOM） | `exportJSON` / `exportCSV` |

## 二、当前的缺点与已知不足

### 2.1 功能与数据

| # | 问题 | 影响 | 现状 |
|---|---|---|---|
| 1 | **AI 识别从未做过真实端到端校准** | 评测报告里的误差全部来自离线管线验证与模拟画像，真实模型误差未知 | 需用户自备 Key 后跑 `node tools/eval-vision.js --live` |
| 2 | **起始重量是粗估**：按「单只哑铃 × 动作系数」线性推算 | 不同动作的力量比例差异大（如侧平举 vs 硬拉），估算可能偏大或偏小 | `suggKg()`，用户需自行调整 |
| 3 | **不支持左右手分开、不支持杠铃** | 与「居家哑铃」定位一致，但无法覆盖杠铃训练者 | 有意不做 |
| 4 | **无云同步 / 无账号** | 换机必须手动导出导入；浏览器清缓存即丢数据 | 有意不做（隐私承诺），但需更强的导出提醒 |
| 5 | **localStorage 容量上限约 5MB**：上传大图（头像 / 背景）会挤占空间 | 图片已压缩到 128px / 1080px，但大量照片缩略图仍可能撑满 | `saveSafe()` 有提示，无主动容量管理 |
| 6 | **知识库匹配仍是关键词计分** | 长句、口语化提问可能误命中；不具备语义理解 | 已加权（长关键词 + 整句命中），仍是规则系统 |
| 7 | **无力量 / 围度曲线** | 只有体重曲线，无法直观看到力量进步 | 待办 P1 |
| 8 | **无训练提醒** | 依赖用户自己记得打开 | 待办 P2（iOS PWA 限制） |

### 2.2 工程与代码

| # | 问题 | 影响 | 现状 |
|---|---|---|---|
| 9 | **`app.js` 单文件约 2900 行** | 模块边界靠注释分区，跨区修改容易互相影响；无法按需加载 | 无构建，拆分需引入模块机制 |
| 10 | **状态结构变更靠手写迁移** | 每加一个字段就要在启动段补一段容错代码，长期易遗漏 | 已有 v7.5 / v7.8 / v7.11 / v8.0 / v8.1 五段迁移 |
| 11 | **无数据版本号（schema version）** | 无法判断用户数据属于哪一版，回滚时风险高 | 缺失，建议补 `STATE.schema` |
| 12 | **自检脚本是自制断言，不是标准测试框架** | 无法生成覆盖率报告，无法被 CI 标准工具消费 | `tools/selfcheck*.js` |
| 13 | **部分函数依赖全局 `STATE`** | 单测需要构造完整环境，可测试性差 | 如 `dataReply`、`renderProfile` |

### 2.3 潜在风险

| # | 风险 | 说明 | 缓解 |
|---|---|---|---|
| R1 | **桌宠 v3 与官方形象差异缩小** | 按视频款式重制后，配色、纹样语言、胸标三项都回到接近原型，可辨识差异显著小于 v2 | 已用三道护栏（自绘简化胸标 / 蛛网限 6 主干 / 零官方素材）；v2 保留可切换。**最终是否可接受需用户确认** |
| R2 | **教学视频时间戳映射未必精确** | 时间戳取自卓叔合集章节，属「最佳可得映射」，未逐条人工核对 | 页面已注明可点开自验；合集未收录的一律用站内搜索兜底，不伪造时间戳 |
| R3 | **PAT 直写在命令行** | 推送脚本需要 `GH_TOKEN`，可能进入 shell 历史 | token 不写入任何仓库文件；建议 90 天过期 |
| R4 | **外部依赖 OpenFoodFacts** | 大陆网络偶发不可达 | 已有重试 + 本地库降级 |
| R5 | **浏览器兼容** | `BarcodeDetector` 仅 Chrome/Edge 安卓；`OffscreenCanvas` / `createImageBitmap` 老浏览器降级 | 已做特性检测与回落 |

## 三、对照成熟 GitHub 开源项目的差距清单

对标口径：中等规模、有稳定维护者的前端开源项目（如 VPet-Simulator、DyberPet、HabitRPG 类个人工具）的通行做法。

### 3.1 文档完整性

| 项 | 成熟项目做法 | 本项目现状 | 差距 | 优先级 |
|---|---|---|---|---|
| README | 一句话定位 + 截图/GIF + 快速开始 + 使用说明 + 常见问题 | ✅ 已覆盖（v8.1 重写），含两套方案选择建议 | 小：缺截图/GIF、缺 FAQ 与故障排查 | P1 |
| LICENSE | 根目录明确的开源许可证文件 | ❌ 无，仅 README 写「个人使用」 | **大**：他人无法合法复用/贡献 | **P0** |
| CHANGELOG | 按版本记录新增/变更/破坏性改动 | ❌ 无，版本历史散落在 `docs/轮次总结.md` | **大**：用户无法判断升级风险 | **P0** |
| 架构文档 | 模块图 + 数据流 + 关键决策记录（ADR） | ⚠️ 有 `docs/架构说明.md`，但无 ADR | 中 | P2 |
| 贡献指南 CONTRIBUTING | 分支策略、提交规范、本地跑通步骤 | ❌ 无 | **大** | P1 |
| 代码注释 | 关键逻辑有「为什么」而不只是「做什么」 | ⚠️ 主要区块有中文注释与版本标记，部分函数缺 | 小 | P2 |
| 文档与代码一致性 | 文档随代码同步更新 | ⚠️ 版本号曾在 mkzip.py / 设置页残留旧值（v8.0 已修） | 中：需建立「改版本先全局搜」的检查 | P1 |

### 3.2 测试与 CI

| 项 | 成熟项目做法 | 本项目现状 | 差距 | 优先级 |
|---|---|---|---|---|
| 自动化测试 | 单元测试 + 集成测试，标准框架（Jest / Vitest / Playwright） | ⚠️ 自制断言脚本，189 项，覆盖行为级 | **大**：无法出覆盖率、无法被标准工具消费 | P1 |
| CI | GitHub Actions：push/PR 自动跑 lint + test + build | ❌ 完全没有 CI | **大**：回归只能靠人工记得跑 | **P0** |
| 覆盖率报告 | 行/分支覆盖率，PR 中展示 | ❌ 无 | 中 | P2 |
| 端到端测试 | Playwright / Cypress 覆盖关键路径 | ❌ 无（仅人工 + headless 截图） | 中 | P2 |
| 预提交钩子 | husky + lint-staged，提交前自动检查 | ❌ 无 | 中 | P2 |
| 依赖扫描 | Dependabot / 安全告警 | 不适用（零依赖），但 SW 缓存与第三方素材需人工留意 | 小 | P3 |
| 测试可在干净环境复现 | 一条命令跑通 | ⚠️ 需先手动装 jsdom 到指定 workspace，路径硬编码在 `selfcheck.js` | 中 | P1 |

### 3.3 版本发布规范

| 项 | 成熟项目做法 | 本项目现状 | 差距 | 优先级 |
|---|---|---|---|---|
| 语义化版本 | MAJOR.MINOR.PATCH，明确含义 | ⚠️ 用 v7.x / v8.x，但无书面规则 | 中 | P1 |
| Git Tag | 每个版本打 tag | ❌ 无 tag（历史被改写为单个提交） | **大** | **P0** |
| Release Notes | GitHub Release 记录变更 | ❌ 无 | **大** | **P0** |
| 分支策略 | main + develop + feature 分支 / PR 合并 | ⚠️ 只有 main，直接原子提交 | 中（单人开发可接受） | P2 |
| 提交信息规范 | Conventional Commits | ⚠️ 中文一句话，无 type 前缀 | 小 | P2 |
| 破坏性变更提示 | 明确标注 BREAKING CHANGE | ⚠️ 数据迁移写在代码注释里 | 中 | P1 |
| 回滚方案 | 明确的回滚步骤 | ✅ 旧皮肤/旧方案均可切换回退；远端保留历史 commit | 小 | — |

## 四、建议的改进顺序

**P0（补齐开源基本盘）**
1. 补 `LICENSE`（建议 MIT 或 GPL-3.0，需你确认）。
2. 建立版本发布规范：打 Git Tag + GitHub Release Notes + `CHANGELOG.md`。
3. 上 GitHub Actions：push 时自动跑 `node --check` + `node tools/selfcheck.js`（装 jsdom 那步写进 workflow）。

**P1（降低长期维护成本）**
4. 补 `CONTRIBUTING.md`：本地跑通步骤 + 改版本的检查清单 + 提交信息约定。
5. 引入 ESLint 配置并入库；先用 JSDoc 给关键函数标类型，不急着上 TypeScript。
6. 给 `STATE` 加 schema 版本号，把散落的迁移段收敛成迁移函数表。
7. README 补截图 / GIF 与 FAQ。

**P2（继续提升）**
8. `app.js` 按职责拆成 ES Modules（免构建，浏览器原生 `import`）。
9. 引入标准测试框架（建议 Vitest），把现有 189 项断言逐步迁移过去，出覆盖率。
10. 补 Issue / PR 模板与行为准则。
11. 补端到端测试（Playwright）覆盖「打卡 → 记饮食 → 导出」主链路。
