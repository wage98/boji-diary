## 二、护城河与最大短板

**护城河（要坚持）**
1. **桌宠常驻** — 竞品没有。它是"打开理由"，不是装饰。
2. **完全离线 + 数据只存本机** — 竞品几乎都在做云同步和社交，隐私敏感用户无选择。
3. **场景足够窄** — 只做"居家哑铃"，动作库不需要大而全，反而不劝退。

**最大短板（要正视）**
1. **录入摩擦** — 吃一顿饭要 3–5 步。AI 识别只解决了"叫什么"，没解决"多少克"。
2. **数据深度不足** — 有打卡、有体重，但没有"力量进步曲线""围度""动作 PR"，长期激励弱。
3. **无跨设备** — 换机靠导出/导入 JSON，对非技术用户是硬伤（但这是隐私承诺的代价）。

## 四、工作流程（每轮迭代 SOP）

这套流程是上一轮踩坑总结出来的，核心是**不让上下文丢失、不让改动裸奔**。

```
① 接续   → 读 docs/轮次总结.md 与 .workbuddy/memory/MEMORY.md，确认基线
② 基线   → node tools/selfcheck.js 必须全绿（不绿先修，不带着红灯开工）
③ 改动   → 最小化、可回滚；新增字段必须带迁移与脏数据兜底
④ 审验   → node --check 语法门禁 → 补攻击式用例 → 全量自检
⑤ 交付   → 更新 docs（审验记录 / 待办 / 轮次总结）→ 推送 → 线上抽检
⑥ 记录   → 追加轮次总结：本轮改动 / 遗留问题 / 下一步计划
```

### Definition of Done（每条改动都要过）

- [ ] `node --check app.js && node --check sw.js` 通过
- [ ] `node tools/selfcheck.js` 全绿，且**新增功能至少有 3 条攻击式用例**
- [ ] 新读取的持久化字段有**迁移 + 脏数据兜底**（非数组/非法值不白屏）
- [ ] 所有用户输入有**夹取与转义**（XSS 用例：`[onerror]`、`img[src="x"]` 节点数为 0）
- [ ] 网络能力有**超时 + 重试 + 降级文案**，不做"假成功"
- [ ] 版本号 / SW 缓存名 / README / 审验记录同步更新
- [ ] 做不到的事**在文档和 UI 里明说**，不写"智能识别"这种含糊词

### 三条纪律（踩过坑才有的）

1. **同名函数重复定义查不出来** — 曾出现新旧 `nahidaReply` 并存，`node --check` 全绿但新逻辑整段是死代码。必须靠行为级测试（真点按钮、真读 DOM）。
2. **"看起来能用"不等于能用** — 组间休息计时器的 DOM/CSS 一直在，但 JS 没接线，一直是死的。改 UI 后必须验证"点了真的会发生什么"。
3. **不敢写"AI 识别"四个字，除非链路真通了** — 未配置服务时必须明确降级，绝不返回编造的食物名。

## 五、度量指标

- **北极星**：周活跃打卡天数（一个人一周能打卡几天）
- 过程指标：①人均每日录入餐次数 ②单次录入耗时 ③拍照功能使用率 ④AI 识别采用率（用了 / 识别了）⑤次日留存
-  health 指标：自检项数与通过率、localStorage 体积（>3MB 要清理照片策略）
