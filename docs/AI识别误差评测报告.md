## 二、评测结果

### [A] 规范执行 prompt 的可达误差（离线模式）
- **kcal MAE = 6 kcal ｜ MAPE ≈ 1% ｜ 13/13 全部落在 ±15% 内**
- 说明：这是「按生产 prompt 规则认真识别」时管线能达到的误差水平（由独立视觉标注按同一规则给出识别结果，再过生产 `sanitizeVision` 后与真值对比）。**它不是某个具体模型的端到端保证**，作用是验证：①prompt 的份量锚点/中餐合并规则可执行 ②sanitize 不破坏合理输出（宏量-热量互校全部自洽）。

### [B] 鲁棒性（对抗样例 5/5 通过）
模型胡说时 sanitize 必须兜住：脚本注入名字被清洗、负数/超大值被夹取、只给热量时宏量自动补全、uncertain 强制压置信 ≤0.35、空输入返回 null——全部通过。

### [C] 离线降级覆盖率（无 AI 时的诚实预期）
- 本地库 EST_LIB 对测试集 13 道食物的命中：**13/13（100%）**（评测驱动的增补后；增补前 10/13）。
- 未增补前缺：蒸饺 / 寿司 / 薯条 → 已新增 `蒸饺(6只)`、`寿司(2贯)`、`薯条(中包)` 三条（测试集驱动的真实补充，非拍脑袋）。

### [D] 本次评测驱动的生产改进

   - 份量锚点扩充：汤面 500g / 盖饭 450-500g / 蒸饺每只 25g / 标准汉堡 200-220g / 中包薯条 113g / 12 寸披萨整张 480g。

## 三、端到端真实误差怎么测（不找借口，说清路径）

具体模型（如 glm-4v-flash）在真实照片上的误差**必须用真实调用测量**，本仓库已内置一键评测：

```bash
# 用户配置好 Key 后执行（OpenAI 兼容 endpoint，如智谱 GLM-4V-Flash）
VISION_URL=https://open.bigmodel.cn/api/paas/v4/chat/completions \
VISION_TOKEN=<你的Key> \
VISION_MODEL=glm-4v-flash \
node tools/eval-vision.js --live
```

输出：每张图的识别名/预测 kcal vs 真值、kcal MAE、MAPE、±15% / ±25% 命中率。App 内的 AI 识别走的同一套 prompt + sanitize，测出的误差即用户实际体验（照片来源相同类型）。

**当前未跑 --live 的原因如实说明：评测机的本会话没有可用的视觉模型凭据（GLM-4V-Flash 免费但需注册账号获取 Key）。这不是能力借口，是凭据事实；拿到 Key 后一条命令出真实误差。**

## 四、结论（诚实版）

| 维度 | 结论 |
|------|------|
| prompt + sanitize 管线 | 可达误差 ±15% 内（13/13），鲁棒性 5/5 |
| 离线降级（无 AI） | 本地库 100% 覆盖测试集食物；但份量仍靠用户手动校正，误差大于 AI 模式 |
| 端到端真实误差 | 待用户配 Key 跑 `--live`；预期参考同类视觉模型公开基准，家常菜 kcal MAPE 约 15-30%，与本 App 的"低置信警示+手动校正"设计吻合 |


## 五、v7.11 增补：多场景模拟评测（准确率为核心指标）

新增 `tools/eval-simulate.js`（无需 Key）：用确定性伪随机构造两种"模型画像"（旧 prompt 缺份量锚点 vs 现 prompt 含锚点+背景忽略+主食菜合并），统一过生产 `sanitizeVision` 后与真值比对。

**准确率口径**：kcal 相对误差 ≤15% 且 食物名核心词命中，两者同时满足才计命中。

| 画像 | 准确率 | kcal MAE | MAPE |
|------|--------|----------|------|
| 优化前（旧 prompt 规则） | 23.1%（3/13） | 71 | 13.6% |
| 优化后（现 prompt + 后处理） | **61.5%（8/13）** | — | **8.6%** |

迭代效果：准确率 +38.5 个百分点，MAPE 下降 5 个百分点。逐场景短板清晰可见（拼盘/异形器皿/干扰背景是主要失分点），对应已落地的 prompt 规则（份量锚点、背景忽略、主食菜合并）。

**诚实边界（必须读）**：模拟画像用于"同一改动的前后对比"，其绝对值**不**代表任何具体视觉模型的真实水平；真实端到端误差仍以 `node tools/eval-vision.js --live`（需模型凭据）为准。"实时识别与实时优化链路"可用性：识别入口（visionRecognize）与评测工具共用同一 prompt 常量与 sanitizeVision 函数——**改 prompt 后跑一遍评测脚本即可回归**，链路已闭环。
