## 二、攻击式自检发现的真实缺陷与修复（逐项）

| # | 用例 | 失败原因（根因） | 修复 |
|---|---|---|---|
| 1 | A11 体重 -5 / 100000 | `dailyGoal()` 直接按体重线性计算，脏数据产生**负蛋白目标 / 百万级热量目标** | `dailyGoal()` 对体重做 `[30,200]` 夹取，非法值回落默认 120g/2000kcal/2000ml |
| 2 | A12 `selDate='abc'` | `getDayType(NaN)` 返回 `undefined` → `PLANS[undefined].ex` **崩溃** | `getDayType` 校验 0–6 否则回落 `rest`；`renderTraining` 增加 `planSafe` 兜底按休息日渲染 |
| 3 | B3 份数输入 -5 / 1e9 | 内部已夹取但**输入框仍显示 -5**，显示与真实值不一致（用户会以为生效） | 新增 `change` 事件回写规范化值（输入过程中不打断，`blur/change` 时纠正） |
| 4 | E3/E6/E7/E8 助手不接上下文、不结合数据、兜底失效 | **新旧 `nahidaReply` 重复定义**：新版本在知识库区块、旧版本在助手区块，函数声明提升后**旧版覆盖新版**，新逻辑整段失效（等于写了一段死代码） | 删除旧版函数，保留带 `CTX` / `dataReply` / `FOLLOW_RE` 的新版；`node --check` 不报此类问题，**必须靠行为级测试** |
| 5 | 功能回归：热量期望 320 | 食物库扩充后「鸡胸肉 100g→150g」基准变化（194 kcal/份 ×2 = 388） | 同步测试期望值；并**校准**两条偏低数据：汉堡 430→492 kcal、薯片 316→402 kcal（对照公认值） |
| 6 | 功能回归：记录份数语义 | 保存时把份数预乘进宏量并写 `q=1`，导致后续 ±0.5 微调语义错乱 | 本地库条目保留「份数」语义（宏量不预乘、`q=份数`）；仅在线条目（每 100g 基数）预乘后 `q=1` 并把克数写进名称 |
| 7 | B2 / E8（测试自身问题） | ①转义后文本仍含 `onerror=alert` 字面量（未成为 DOM 属性，实为安全）；②兜底文案是「不太**确定**」被断言成「不确定」 | 断言改为检查 `img[src="x"]` / `[onerror]` 节点数为 0；文案断言同步 |

> **教训**：`node --check` 与静态断言**证明不了功能可用**。第 4 项（重复函数定义覆盖）是纯静态检查永远发现不了的，只有"真问一句、真看回答"才会暴露。

## 三、覆盖的攻击面（未再失败的项）

- **脏数据**：localStorage 存 非JSON / `null` / 数组 / 字符串字面量；`checkins` 为字符串；`meals` 为数组；`scores` 为字符串；`checkins` 含非法日期键（`abc`）；`water` 为字符串数字（迁移 750ml）；`profile` 缺字段；体重极值。
- **异常输入**：搜索含正则元字符 `.*(?:)|[\]`；食物名注入 `<img src=x onerror=alert(1)>`（已转义、未生成节点）；份数 0/-5/1e9；覆盖热量为负；昵称 500 字（截断 12）；身高体重越界不写入。
- **边界值**：月历跨年到去年 12 月；闰年 2 月 29 天 / 平年 28 天；饮水减到 0 不为负；份量减到 0.5 不再减小；删除不存在条目；未打卡日期不给评分；评分为空仅提示。
- **失败兜底**：在线查询 `fetch` reject / 返回非 JSON / 空 `products` / 无 `fetch` 环境（老浏览器）→ 均落到"用本地库估算"提示；照片压缩失败仍可手动校正；导入非法 JSON 提示而非崩溃。
- **回归**：返回键层栈、月历打卡标记、饮水 ml、休息计时器、时间戳出处说明、导出 CSV 的 UTF-8 BOM（按字节校验）。

## 四、纪律（后续必须遵守）

1. 任何改动后至少跑：`node --check` + `tools/selfcheck.js`。
2. 新增功能必须**同时**补一条攻击式用例（正常路径之外的脏数据路径）。
3. 涉及 `localStorage` 结构变更，必须写**迁移代码 + 一条脏数据用例**（v7.5 的"杯→ml"迁移即如此）。
4. 严禁同一函数重复定义；提交前用行为级测试兜住。
