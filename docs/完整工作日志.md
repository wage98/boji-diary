## 一、v2 — 训练动作 ↔ B站视频章节对齐（建立“可自验”纪律）

**步骤 1.1 · 目标**：用户怀疑“训练日动作”和视频对不上，要求用超链接把动作映射到真实 B站章节。
- **关键改动**（`app.js`）：定义 `BV='https://www.bilibili.com/video/BV1FY4y1y7Vh'`，`vid(t,label)=>({url:${BV}/?t=${t}, label})`，为每个动作填真实章节秒数（如哑铃卧推 `?t=139`）。
- **为什么**：凭感觉写映射不可信；带时间戳的深链点开即可核对，符合用户“保持审验”的要求。
- **自验**：打开 `?t=139` 确跳到卓叔《30个家庭哑铃增肌动作教学》对应章节；在代码注释标注时间戳来源与“可自验”说明。

**步骤 1.2 · 目标**：把早期“静态图助手指”升级为动态桌宠（用户要“奶龙”当常驻宠物，非贴图）。
- **关键改动**：用内联 SVG + CSS 动画做动态宠物（避免 `<use href>` 在 Shadow DOM 无法被 CSS 动画的坑，改为真实 DOM 节点）。
- **为什么**：静态图无法体现“陪伴感”；内联 DOM 才能逐帧控制动画。
- **自验**：`node --check` 通过；浏览器中宠物有呼吸/招手循环动画。

> 注：v2–v5 的“奶龙/Nailong”形象在 v6 被整体废弃（用户要求改用已有动漫角色），相关代码已归档至 `_source/`，正文不再保留，但“动态桌宠 + 情绪循环”的思路被继承。

## 十、v7.3 — 经验总结第四节三个迭代方向落地（本轮核心）

> 用户要求：工作日志更详细 + 按经验总结末尾“优化迭代方向”优化。三个方向：①真实 PWA ②接入 Live2D/更生动 ③计划可编辑+渐进超负荷。下面逐子步骤记录。

### 方向 ① 真实 PWA（桌面常驻/离线可达）

**步骤 10.1 · 新增 `manifest.json`**
- 关键字段：`name/short_name`、`display:"standalone"`（独立窗口，像原生 App）、`start_url:"."`、`orientation:"portrait"`、`background_color/theme_color:"#F3F0FB"`、`icons:[{src:"assets/icon.svg",sizes:"any",type:"image/svg+xml",purpose:"any maskable"}]`。
- 为什么：PWA 可被“添加到主屏幕/安装”，启动即全屏，比单纯网页更接近“桌面常驻”。
- 自验：`JSON.parse(manifest.json)` 合法；`display==='standalone'`、`icons[0].src` 正确。

**步骤 10.2 · 新增 `assets/icon.svg`**
- 内容：圆角方形薄荷→淡紫→粉渐变底 + 圆脸双丸子头宠物 + 招牌发饰宝珠 + 草元素粒子 + “训练日记”文字（呼应小练草元素主题，且为自绘 SVG，无版权风险）。
- 为什么：PWA 需图标；SVG 矢量可任意缩放且体积小，规避 PNG 二进制生成依赖。
- 自验：HTTP 200 可访问；浏览器地址栏 manifest 图标解析正常。

**步骤 10.3 · 新增 `sw.js`（Service Worker 离线缓存）**
- 逻辑：`install` 预缓存 app shell（index.html/app.js/styles.css/manifest.json/icon.svg/3 张 nahida webp）；`activate` 清理旧缓存；`fetch` 走“缓存优先、网络回退并更新缓存”，非 GET 直接放行。
- 为什么：断网或二次打开时桌宠秒开，真正“常驻”可用。
- 自验：HTTP 200；`install/activate/fetch` 与 `caches.open` 结构齐全。

**步骤 10.4 · 接入**
- `index.html`：`<link rel="manifest" href="manifest.json">` + `<link rel="apple-touch-icon" href="assets/icon.svg">`。
- `app.js` `boot()`：`if('serviceWorker' in navigator){ window.addEventListener('load',()=>navigator.serviceWorker.register('sw.js').catch(()=>{})); }`（file:// 静默跳过，http/localhost 才生效）。
- 自验：本地起 `python -m http.server 8080`，curl 验证 manifest/sw/icon/index 均 200；`app.js` 含注册代码。

### 方向 ② 桌宠“活起来”（轻量 Live2D 等效，诚实处理版权约束）

**步骤 10.5 · 约束说明（实事求是）**
- 真实 Live2D 需要角色的 Cubism 绑定模型（含眨眼/表情/肢体骨骼）。小练的官方 Cubism 模型非自由分发授权，无法直接嵌入；GitHub 桌宠框架（如 Live2D Cubism Web SDK、BongoCat）的范式可参考，但模型资产受版权限制。
- 决策：交付**主题化轻量等效**，并保留清晰的集成钩子（今后若有授权模型，可在 `#pet` 内替换 `<img>` 为 `<canvas>` + Cubism SDK），不在无授权下伪造“Live2D”。

**步骤 10.6 · 招牌发饰宝珠浮动**
- `index.html`：`.pet-body` 内加 `<span class="pet-akuma a1">`、`<span class="pet-akuma a2">`（小练标志性两侧漂浮宝珠）。
- `styles.css`：`@keyframes akuma` 上下浮动 + 轻微旋转（a2 延迟 .8s、换粉色），`pointer-events:none` 不挡交互。
- 为什么：宝珠是角色最强识别点，浮动即“活”，且零素材依赖。

**步骤 10.7 · 草元素粒子上升**
- `index.html`：`.pet` 内加 `<div class="pet-particles"><i></i><i></i><i></i></div>`（3 颗草/粉/紫光点）。
- `styles.css`：`@keyframes floatup` 由下往上淡入淡出上升（不同延迟），呼应小练“草元素”神明设定。
- 为什么：持续微动让常驻桌宠始终有“生命感”，不依赖用户触发。

**步骤 10.8 · 无障碍**
- `prefers-reduced-motion` 媒体查询增加 `.pet-akuma,.pet-particles i{animation:none !important;}`，尊重系统“减少动态效果”。
- 自验：CSS 含 `.pet-akuma{`、`.pet-particles i{`、`@keyframes floatup`、reduced-motion 覆盖；HTML 含对应 DOM。

### 方向 ③ 训练计划可编辑 + 哑铃渐进超负荷

**步骤 10.9 · 状态字段**

# 十四、v7.4 移动端专项修复（2026-09-27 18:20–18:45，用户当面提的四条 + 同步答疑）

用户按优先级下达四类问题并要求「逐项说明改动位置与效果」，同时要求回答是否会直接提交 GitHub、手机能否自动同步。以下按 目标 → 改动位置 → 为什么 → 如何自验 逐步骤记录。

## P0-1 返回键：应用程序层导航栈（不再直接退出 App）

**目标**：按物理/系统返回键回到上一页或关闭当前弹层；只有在首页且无历史时才提示「再按一次退出」。

- **步骤 1 · 定位**：全项目检索 `popstate` / `history`，结果为 **0 处**——根因确认：代码从未做历史管理，安卓返回必然直接退出。
- **步骤 2 · 加层栈**（`app.js` 新增 `NAV` / `CLOSERS`）：
  - `NAV.stack` 记录已打开层（module / assistant / onboard / done-modal / food-sheet）；`NAV.g` 记录由我们压入的 history 条数。
  - `navOpen(id)`：**先垫一条 shield 再压本层**（顺序不能反，否则返回键会先弹掉 shield）。
  - `navUIClose(id)`：UI 上的 ✕ / 完成 → 先关 DOM，再用 `history.go(-n)` 一次性回退对应层数，并用 `NAV.suppress` 抵消随后触发的 popstate，保证堆栈不错位。
  - `popstate` 统一处理：有层 → 关最上层；无层 → 进入退出确认流程（2.2s 内第二次才真退出，`window.close()` + 兜底 `history.back()`）。
- **步骤 3 · 收口所有开关入口**：`openPanel()` 统一调 `navOpen()`；`closePanel()` 改为 `navUIClose()`；`ob-save` / `done-ok` / 食物面板取消按钮全部改走 `navUIClose`；`finishDay()` 与 `showOnboard()` 改走 `navOpen`。
- **为什么这样设计**：返回键行为必须与 UI 关闭按钮共用一套状态，否则会出现「按返回关了面板，但 UI 记录还留着」的错位。
- **自验**：jsdom 真机级断言——打开模块后 `history.back()` → `#module` 关闭且 stack 归零；首页按返回 → toast 文案「再按一次退出训练日记」；2.2s 内第二次 → `window.close()` 被调用。全部 PASS。

## P0-2 饮食页：一个未定义变量导致的整页无响应

- **步骤 1 · 定位根因**：`renderDiet()` 末行模板字符串写成 `${mf}`，而累计变量实际叫 `fTot`。文件顶部有 `'use strict'`，读取未声明变量直接抛 `ReferenceError`，于是 `goModule('diet')` 在 `renderModule` 处中断，连 `openPanel` 都没执行 → 点击后**毫无反应**。
- **步骤 2 · 修正**：`${mf}` → `${Math.round(fTot)}`；同时暴露只把它当 halogen（而非语法问题）的隐患——已用静态断言 `!/$\{mf\}/` 锁死。
- **步骤 3 · 顺手补强体验**（原「+ 添加食物」是 `Math.random()` 随机塞一样，不可控）：改为底部弹出面板 `openFoodSheet()`，列出全部食物库并支持**填份数（最小 0.5）**；每条记录带 `− / +` 改份数、`✕` 删除，满足「增/改/删」。
- **自验**：jsdom 断言——点「饮食」面板打开、四大餐次与「今日总计」渲染成功、新增后 `STATE.meals` 写入 `{n:"鸡胸肉(100g)", q:1.5}`、`+` 后 q=2、`✕` 后数组清空、面板自动关闭。全部 PASS。

## P1 布局：整屏适配（信息不减）

- **步骤 1 · 定位**：`styles.css` 里手机外壳写死 `.bezel{width:390px;height:844px}`，`body{overflow:hidden}`，**全站没有任何移动端适配** → 真机必然溢出且因禁止滚动而看不全。
- **步骤 2 · 新增 @media 块**：判定条件取 `max-width:560px` **或** 触屏无悬停 `(pointer:coarse) and (hover:none)`（这样电脑预览仍保留手机外壳效果，不会被误触发）。块内：外壳转透明无边框、`height:100dvh`（带 `100vh` 回退）、隐藏模拟状态栏与刘海、等比例压缩时钟/卡片/桌宠/dock 字号尺寸、用 `env(safe-area-inset-*)` 适配安全区。另加 `(max-width:560px) and (max-height:680px)` 矮屏二次压紧。
- **步骤 3 · 覆盖层改 fixed**：`.modal-mask` / `.toast` / `.rest-timer` 由 `absolute` 改 `fixed`，避免跟随文档产生整页滚动；新增的食物面板自带滚动（`max-height:42vh`），内容再长也不撑出页面。
- **为什么不动 viewport**：它是 `width=device-width, initial-scale=1.0, viewport-fit=cover`，本身正确；真正的问题是固定 390×844 的装饰外壳 + 绝对定位覆盖层，改这两处即可，无需破坏信息结构。

## P2 数据能力：导出 / 导入 / 撤销

- **导入 JSON**（`importJSON`）：`<input type=file>` + FileReader，合并默认值后重载，随时回滚到备份。
- **训练页撤销打卡**（`#day-undo`）：已有记录可删除打卡标记（动作勾选保留），契合「根据健身情况及时调整」。
