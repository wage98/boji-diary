# 训练日记

手机桌面常驻的**居家哑铃增肌记录 App**，带一只会聊天的二次元桌宠。

纯前端 PWA：无构建、无后端、无账号，所有数据只存在你自己的浏览器里。

- 在线体验：<https://wage98.github.io/boji-diary/>
- 当前版本：1.0.0 ｜ 许可：个人使用（角色素材溯源见 [`assets/CREDITS.md`](assets/CREDITS.md)）

---

## 它能做什么

| 模块 | 具体内容 |
|---|---|
| **训练** | A / B 两套完整方案（见下），每套 4 个训练日 × 6 个动作；组次与重量记录、渐进超负荷建议（+2.5kg）、组间休息计时、计划可编辑、教学视频时间戳可点开自验 |
| **自定义动作** | 自建动作的部位 / 组数 / 次数 / 休息 / 要点，休息日也能练，重量与完成状态同样记录（上限 20 个） |
| **饮食** | 拍照 → AI 视觉识别（可插拔，默认关闭）/ 条码 / 历史高频 / 在线库 / 81 项本地库；结果带**置信度徽章**，名称·份量·热量全字段可校正 |
| **数据** | 连续打卡、月历打卡视图、每日训练评分、近 7 日柱状图、体重曲线（手写 SVG）、JSON / CSV 导出与导入 |
| **助手** | 78 条带证据等级的知识库 + 最近 5 轮上下文 + 结合本机数据回答（今天练什么 / 蛋白够吗 / 本周统计 / 体重趋势） |
| **桌宠** | 4 种形象统一切换（小蛛视频同款 / 早期版 / 现版 / 小练），10 种情绪、眨眼、连点彩蛋、打字机气泡、顶边悬挂、拖拽吸附 |

## 两套训练方案：怎么选

两套方案**各自完整、互不交叉**，都是「推 / 拉 / 腿 / 核心」4 个训练日 × 6 个动作，覆盖胸、背、肩、臂、腿、臀、核心。区别在于家里有没有一张卧推椅（或可调角度的稳固长凳）。

| | **A 套 · 居家有卧推椅** | **B 套 · 居家无卧推椅** |
|---|---|---|
| 需要 | 哑铃 + 卧推椅（或稳固长凳） | 只需哑铃 + 地板（可选稳固凳子 / 台阶） |
| 上肢推类 | 平板 / 上斜哑铃卧推、仰卧臂屈伸 | 地板哑铃卧推、地板飞鸟、哑铃俯身臂屈伸 |
| 下肢与核心 | 保加利亚分腿蹲（后脚搭椅）、肩撑椅臀桥 | 相扑深蹲、原地分腿蹲、单腿臀桥 |
| 动作行程 | 卧推可以放得更低，胸肌拉伸更充分 | 地板卧推肘触地即停，行程受限但**对肩更友好、更安全** |
| 典型场景 | 家里已有一张椅子，想让动作更接近健身房版 | 租房 / 宿舍，不想为大件腾空间 |

**选择建议**

- 家里有卧推椅或可调长凳 → 选 **A 套**，卧推行程和角度调整空间更大，上胸和背部的动作选择更多。
- 只有哑铃和地板 → 选 **B 套**。地板卧推虽然行程短，但省掉了肩关节在最低点的压力，作为家庭长期方案同样能练到位。
- 不确定先选哪套 → 用 **B 套**起步，适应 2–4 周后再看是否要添置椅子；两套切换不会丢任何打卡和重量记录。

切换位置：App 内「我的 → 训练方案」。

每个动作都标注了：**动作名 / 目标肌群 / 组数×次数 / 动作节奏（离心-底停-向心）/ 呼吸方式 / 组间休息 / 起始建议重量 / 动作标准 / 常见错误 / 教学视频**。

## 快速开始

```bash
# 1. 语法门禁（改完代码先跑这个）
node --check app.js && node --check sw.js

# 2. 安装自检依赖（一次性）
cd C:/Users/WaGe/.workbuddy/binaries/node/workspace
npm i jsdom --registry=https://registry.npmmirror.com

# 3. 跑完整自检（功能回归 41 项 + 攻击式 148 项）
node tools/selfcheck.js

# 4. 生成桌宠形象预览页（可选，用于肉眼验收自绘 SVG）
node tools/gen-pet-preview.js   # 输出 docs/桌宠形象预览.html
```

打开方式：双击 `index.html` 用浏览器打开即可（`file://` 下 Service Worker 不注册，功能不受影响）。
需要完整 PWA 行为时，用任意静态服务器托管，再以 `http://localhost` 访问。

推送到 GitHub（本机 `git` 协议被阻断，走 Git Data API）：

```bash
GH_TOKEN=<你的PAT> node tools/push.js "提交说明"
```

## 使用说明

**首次打开**：填身高 / 体重 / 单只哑铃重量。这三个值会即时影响起始建议重量、每日蛋白与热量目标、饮水目标。

**首页**：今日训练卡（点「开始训练」进入）、今日热量与蛋白进度、桌宠常驻右下。

**训练页**：按周几自动给出训练日（周日休息）。每个动作可填实际重量、标记完成，完成后自动进入组间休息倒计时；动作全部达标后解锁「+2.5kg」建议。点「✎ 编辑计划」可改组数与次数。

**饮食页**：每餐有「📷 拍下这一餐」和手动选择两条路径。拍照后若未开启 AI 识别，会走条码 / 在线库 / 历史高频 / 本地库匹配，结果页可改名称、份量、热量，确认后才写入。

**数据页**：月历打卡视图（✓ 表示已打卡，点日期可给当天训练评分）、近 7 日柱状图、体重曲线。

**我的**：档案实时编辑、训练方案切换、桌宠形象与外观（含背景 / 教练名与头像）、AI 识别设置与连通性测试、数据导出导入。

## 技术说明

- **无构建、无框架**：原生 HTML/CSS/JS，改完刷新即可，没有编译步骤和依赖树。
- **数据存本机**：`localStorage` 键 `boji_v7`，导出 JSON 可自行备份。写入失败会明确提示（不会静默丢数据）。
- **AI 识别是可选插件**：需要云端视觉模型才能做真识别，默认关闭。未配置时明确降级为条码 / 在线库 / 历史 / 本地匹配，**不返回编造结果**。自建代理见 [`server/README.md`](server/README.md)。
- **桌宠形象全部自绘**：分层 SVG，没有任何第三方角色素材进默认路径（官方素材仅作为可切换的备选，溯源见 `assets/CREDITS.md`）。

## 已知边界

- **AI 识别默认关闭**：真识别必须调用云端视觉模型，需自备 Key 或自建代理。
- **识别误差**：即便开启 AI，家常菜混合餐的估算误差仍可能在 ±15~35%，结果页强制可校正，UI 已如实标注。
- **条码识别**：依赖 `BarcodeDetector`，仅 Chrome/Edge 安卓支持（iOS 自动隐藏入口，手动路径完整）；OpenFoodFacts 在大陆网络偶发不可达，已有重试与降级。
- **只支持单只哑铃重量递增**：起始建议重量按「单只哑铃 × 动作系数」估算，不区分左右手、不支持杠铃。
- **无账号、无云同步**：换机请用导出 / 导入 JSON。
- **桌宠形象版权**：小蛛「视频同款」版本在配色与纹样上接近经典红蓝形象，已通过自绘简化胸标、限制蛛网主干数、不使用任何官方素材来拉开差异；如需更强的差异化，可在「我的 → 桌宠形象」切回「小蛛 · 现版」。
